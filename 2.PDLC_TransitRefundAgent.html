Architecture Decision Records
ADR-001 · CTO APPROVED
LangGraph Over LangChain for Orchestration
Three product requirements LangChain DAGs cannot meet: payment retry requires graph cycles, HITL requires mid-graph interrupt/resume, crash recovery requires stateful checkpointing. LangGraph satisfies all three. LangChain rejected — not an engineering preference, a product necessity.
ADR-002 · CTO + COMPLIANCE APPROVED
RAG Over Fine-Tuning for Policy Retrieval
Policy documents change quarterly. Fine-tuned models need 2–4-week retraining cycles. RAG enables same-day policy updates via admin console. Critical: compliance team can own policy updates without engineering involvement — a hard requirement from the Phase 1 Legal interview.
ADR-003 · PM OVERRULED ENGINEERING
MCP Protocol for All Tool Integration
Engineering proposed custom REST clients per service. PM declined. Without MCP: 6 agents × 6 systems = 36 bespoke integrations. With MCP: 6 server implementations + 1 standard client interface. Swap payment gateway = replace 1 server, zero agent code changes. Engineering accepted after seeing the maintenance cost projection.
ADR-004 · CFO HARD REQUIREMENT
$500 Cap at Payment API Layer — Not Prompt Layer
CFO requirement: no financial guardrail that relies on prompt engineering. Prompts can drift or be jailbroken. The Payment Gateway MCP Server enforces the cap at the API — returns AMOUNT_EXCEEDS_CAP regardless of LLM output. Infrastructure enforcement, not AI-layer policy. Non-negotiable for autonomous payment authorisation.
ADR-005 · CALIBRATED ON HISTORICAL DATA
85% Confidence Threshold — Precision-Recall Tradeoff
Simulated on 90 days of historical event data. At 90%: 22% HITL rate — operationally unsustainable (team capacity). At 80%: 3.1% error rate on auto-processed — exceeds 0.3% target. At 85%: 6% HITL + 0.28% error on auto-processed. Optimal point on the precision-recall curve for this operation size.

SPRINT 2 · BLOCKER RESOLVED IN WEEK 3
GTFS Schema Mismatch → Scope Descope
GTFS MCP Server found operator feed missing fields for 3 disruption types (weather, security, multi-line). PM decision: descope weather disruptions from V1 — affects 11% of events. Backlog updated, PRD amended, V2 roadmap updated. No sprint delay incurred. Stakeholders briefed same day.
SPRINT 4 · PM HELD THE LINE
Shadow System is Non-Negotiable
Engineering proposed skipping shadow system to accelerate velocity. PM declined — shadow system was a Phase 2 gate commitment and a Responsible AI requirement. Vindicated in week 6 of testing: shadow system caught a systematic eligibility miscalculation for monthly pass holders that manual comparison would not have surfaced for months.
SPRINT 6 · MID-SPRINT PRIORITY CHANGE
Idempotency Keys Elevated to P0
Load testing surfaced a gateway retry scenario that could generate duplicate refunds. PM elevated idempotency key implementation over sprint stretch goals mid-sprint. Rationale: a duplicate refund at 1,200-patron scale creates simultaneous financial exposure and patron trust damage. Financial integrity is always P0.
SPRINT 8 · SCOPE CUT TO SHIP ON TIME
Email Notifications Cut to V1.1
Email backend vendor integration ran 3 weeks late. Analysis: 94% of patrons covered by push + SMS. PM decision: launch without email, ship V1.1 patch 3 weeks post-launch. Stakeholders briefed proactively — no executive surprise at launch. Email added on schedule.

Optimization Experiments — Hypothesis-Driven
EXPERIMENT-001 · MONTH 2 · RETRIEVAL
Hybrid Retrieval Improves Policy Lookup Precision
Hypothesis: adding BM25 alongside semantic search improves precision on exact policy clause references like "Section 4.2" vs. semantic-only. A/B on 200 events. Primary metric: eligibility accuracy. Secondary: avg_confidence on signal failure events.
✓ CONFIRMED — Eligibility accuracy +1.8%. Avg confidence +0.04 on signal failures. Shipped in v1.2.
EXPERIMENT-002 · MONTH 3 · CONFIDENCE
Per-Type Confidence Thresholds Reduce Unnecessary HITL
Hypothesis: signal failures (high policy clarity) can use 90% threshold. Novel events need 80%. Uniform 85% is suboptimal at both ends. Tested on 60-day data slice with controlled comparison to uniform baseline.
✓ CONFIRMED — HITL rate on known event types reduced 2.1%. Novel escalation rate unchanged. Shipped v1.3.
EXPERIMENT-003 · MONTH 4 · NOTIFICATION
Personalised Notification for Monthly Pass Holders
Monthly pass holders receive account credit, not card refund. Generic "refund processed" was causing confusion and follow-up inquiry calls — disrupting the <1/100 patron inquiry rate target.
✓ CONFIRMED — Pass holder inquiry rate: 2.1 → 0.4 per 100 patrons. CSAT for pass segment +0.3 in first 30 days.
EXPERIMENT-004 · MONTH 5 · PAYMENT
Retry Backoff Optimisation for Gateway Bursts
Current: 2s base, ×2 multiplier. Hypothesis: 1.5s base, ×1.5 multiplier reduces total retry window for small gateway bursts without impacting large outage behaviour.
⚠ PARTIAL — Faster for small bursts (<200 patrons). Worse for large gateway outages. Solution: segmented by event size. Fast backoff for <200, standard 2×2 for 200+.
