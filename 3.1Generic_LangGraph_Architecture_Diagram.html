② Graph Definition — Nodes + Edges
# ── Build the LangGraph ───────────────────────── graph = StateGraph(AgentState) # Add all nodes graph.add_node("disruption_analysis", disruption_analysis_agent) graph.add_node("eligibility_validation", eligibility_agent) graph.add_node("compliance_check", guardrail_agent) graph.add_node("refund_calculation", refund_calc_agent) graph.add_node("payment_execution", payment_agent) graph.add_node("notification_delivery", notification_agent) graph.add_node("hitl_queue", hitl_interrupt_handler) # Entry point graph.set_entry_point("disruption_analysis") # Unconditional edges graph.add_edge("disruption_analysis", "eligibility_validation") # Conditional: confidence gate after eligibility graph.add_conditional_edges( "eligibility_validation", route_on_confidence, # routing function { "proceed": "compliance_check", "escalate": "hitl_queue", } ) # Conditional: guardrail gate graph.add_conditional_edges( "compliance_check", route_on_compliance, { "passed": "refund_calculation", "failed": "hitl_queue", } ) # Conditional: cap exception gate graph.add_conditional_edges( "refund_calculation", route_on_cap_exceptions, { "no_exceptions": "payment_execution", "exceptions_exist": "hitl_queue", } ) # Conditional: payment retry loop (cycle) graph.add_conditional_edges( "payment_execution", route_on_payment_status, { "retry": "payment_execution", # CYCLE! "proceed": "notification_delivery", } ) # HITL routes back to originating node graph.add_conditional_edges( "hitl_queue", route_on_supervisor_decision, { "resume_eligibility": "eligibility_validation", "resume_compliance": "compliance_check", "resume_calculation": "refund_calculation", "manual_mode": END, } ) # Terminal edge graph.add_edge("notification_delivery", END) # Compile with checkpointing (enables HITL interrupt) app = graph.compile( checkpointer=SqliteSaver.from_conn_string(":memory:"), interrupt_before=["hitl_queue"] )
③ Routing Function Example — Confidence Gate
def route_on_confidence(state: AgentState) -> str: """ Conditional edge routing function. Evaluates agent confidence scores and returns routing key. LangGraph calls this after eligibility_validation node completes. """ scores = state["confidence_scores"] avg_confidence = sum(scores.values()) / len(scores) if avg_confidence < 0.85: # Update state with HITL reason before routing state["hitl_required"] = True state["hitl_reason"] = f"Low confidence: {avg_confidence:.2%} < 85% threshold" return "escalate" # → hitl_queue node return "proceed" # → compliance_check node def route_on_payment_status(state: AgentState) -> str: """Handles the payment retry CYCLE in LangGraph.""" retry_queue = state["retry_queue"] retry_counts = state["retry_count"] max_retries = 3 # Filter out patrons who've exceeded max retries still_retrying = [ p for p in retry_queue if retry_counts.get(p, 0) < max_retries ] if still_retrying: state["retry_queue"] = still_retrying return "retry" # ← CYCLE BACK to payment_execution return "proceed" # → notification_delivery

STEP 01 · T+0s
Disruption Event Triggers the Graph
GTFS real-time feed detects signal failure on Blue Line. Anomaly score exceeds threshold. Cloud Pub/Sub publishes a structured event message. LangGraph runtime receives the message and calls app.invoke(initial_state) — initialising the AgentState object and setting the entry point to disruption_analysis.
event = {disruption_id: "DIS-2024-0847", line_id: "BLUE", disruption_type: "SIGNAL_FAILURE", severity: 0.82, start_time: "06:15:00", end_time: "09:30:00"} app.invoke(event, config={"thread_id": "DIS-2024-0847"})

STEP 02 · T+2s
Disruption Analysis Agent Builds Trip Manifest
The first node executes. LLM invokes two tools via function calling: get_gtfs_trips() retrieves all trips on the Blue Line between 06:15 and 09:30 — returns 1,247 trip records. query_passenger_db() cross-references each trip with fare transaction data. PII tokenization runs immediately — all patron identifiers replaced with secure tokens before anything proceeds.

STEP 03 · T+8s
Eligibility Agent — RAG Retrieval + LLM Reasoning
The most complex step. For each patron, the agent runs a hybrid retrieval query against the Vertex AI Vector Search index — semantic similarity search for conceptual policy matches combined with BM25 keyword search for exact fare rule terms. Retrieved chunks are filtered at 0.7 cosine similarity threshold. LLM then reasons over the retrieved context to make an eligibility determination per patron. Chain-of-thought reasoning trace is logged for every decision.
retrieved_chunks = rag.hybrid_search( query=f"signal_failure refund policy {fare_category}", semantic_weight=0.6, bm25_weight=0.4, threshold=0.7 ) decision = llm.reason(patron_context, retrieved_chunks) # decision.confidence = 0.91 ← above 0.85 threshold ✓ # eligibility_result: 1189 eligible, 58 excluded

STEP 04 · T+12s
Confidence Gate — Conditional Edge Evaluation
LangGraph calls the route_on_confidence() routing function with the current state. Average confidence across the eligibility batch is 0.91 — above the 0.85 threshold. The conditional edge routes to compliance_check. If confidence had been below 0.85, the graph would have paused at the HITL interrupt node, notified the supervisor dashboard, and waited for human approval before proceeding.

STEP 05 · T+14s
Compliance Guardrail Agent — Three Sequential Checks
The guardrail agent runs three independent checks in sequence. Rail 1: NeMo input rail scans the accumulated state object for adversarial patterns, prompt injection attempts, or policy override signals — PASS. Rail 2: PII tokenization audit verifies no plain-text sensitive data exists anywhere in the state — PASS. Rail 3: Output schema pre-validates the eligibility manifest structure before it's passed to the calculation agent — PASS. All three pass — the route_on_compliance() function returns "passed".

STEP 07 · T+22s → T+65s
Payment Orchestration Agent — Individual Refunds + Retry Cycle
Fires 1,189 individual refund requests asynchronously to the payment gateways, routed by payment method. Each request carries a unique idempotency key to prevent double-refund. 1,156 succeed immediately. 33 timeout. LangGraph's cycle kicks in — the conditional edge routes BACK to payment_execution with the 33 in the retry queue. Exponential backoff retry: attempt 2 after 2s, attempt 3 after 4s. 31 of 33 succeed on retry. 2 routed to failed-payment queue for manual recovery.

Notification Agent — Real-Time Per-Patron Delivery
Critically, notifications fire per patron on individual payment confirmation — not after the entire batch. Patron #1 gets their push notification at T+25s when their individual refund clears. This is the design choice that creates the "real-time" experience. Multi-channel: push notification first (78% app-installed), SMS fallback, email tertiary. Message personalised with exact refund amount, explanation, and timeline. Multi-lingual based on account preferences.

KEY LANGGRAPH CONCEPTS
Why LangGraph vs LangChain?
LangChain alone: Linear sequence only. No cycles, no conditional branching, no state persistence across steps.
LangGraph adds:
→ Stateful graph — shared AgentState travels through all nodes
→ Cycles — payment retry loop impossible in chain
→ Conditional edges — route on confidence, compliance, caps
→ Interrupts — pause graph at HITL node, resume after human
→ Checkpointing — crash recovery from last good state
HITL Interrupt Mechanism
LangGraph's interrupt_before=["hitl_queue"] pauses graph execution before the HITL node runs. The graph state is checkpointed. A supervisor reviews the state in the dashboard. On approval: app.invoke(None, config) resumes from the checkpoint. On rejection: graph terminates and switches to manual mode.
Payment Retry Cycle
LangGraph supports cycles — a node can route back to itself or a previous node. The payment retry cycle is the key reason LangChain alone was insufficient. The graph loops back to payment_execution with only the retry queue — not the full patron list. State persists between iterations.
Checkpointing = Crash Safety
Every state transition is checkpointed to persistent storage. If the system crashes after processing 800 of 1,189 payments, on restart LangGraph reads the checkpoint, identifies the 389 remaining, and resumes — without reprocessing the 800 already complete. Idempotency keys at the payment gateway prevent any double-refund risk.
